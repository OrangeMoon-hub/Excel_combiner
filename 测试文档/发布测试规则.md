# Excel Combiner 发布测试规则

> 适用范围：所有合并、拆分版本
>
> 文档职责：定义发布必须满足的质量门槛，是发布测试的唯一权威来源
>
> 最后更新：2026-10-06
>
> 当前状态：已生效；历史具体用例见 `测试方案.md`

## 1. 规则等级

- **P0 发布阻断**：任一项失败，不得合入 `main`、打标签或发布 EXE。
- **P1 能力阻断**：涉及该能力时必须通过；未通过时必须在处理前阻止或明确警告，并从 README 的已支持能力中移除。
- **P2 兼容记录**：允许发布，但必须记录验证范围、失败样例和用户可见边界。

“CI 绿色”只代表自动化项目通过。发布还必须完成本规则要求的真实 Microsoft Excel 兼容性检查。

## 2. 所有版本都必须通过的 P0 门槛

### 2.1 原文件安全

1. 合并模板、待合并文件和拆分来源文件的内容不得被修改。
2. 输出路径不得与任一输入路径相同；重复运行不得静默覆盖已有结果。
3. 用户取消、输入错误、文件被占用、权限不足或处理中断时，不得留下可被误认为成功结果的半成品。
4. 写入应先完成临时文件，再以原子方式形成最终结果；失败时清理本次临时产物。

### 2.2 文件可打开且不得要求修复

每个输出文件必须同时满足：

1. ZIP/OpenXML 包完整，内部 XML 可解析；
2. 能被 openpyxl 重新打开并读取关键 Sheet、维度和单元格；
3. 能被受支持的 Microsoft Excel 正常打开、计算、保存并再次打开；
4. 不出现“发现不可读取的内容”“需要修复”“已删除的记录”“文件格式与扩展名不匹配”等提示；
5. Excel 不得生成修复日志。只要出现修复提示，即使肉眼看起来数据仍在，也判定为发布失败。

### 2.3 数据类型不可擅自改变

对 `.xlsx/.xlsm` 普通数据单元格，合并列重排和拆分分组前后必须保持原类型：

- 数值仍为数值，包括整数、小数、负数和零；
- 布尔值仍为布尔值；
- 日期/时间仍为日期/时间；
- 文本仍为文本，`00123` 等文本编号不得丢失前导零；
- 空单元格不得变成可见的 `0`、`None`、`nan` 或空格文本；
- Excel 错误值不得被静默改写成普通文本或空白。

表头为稳定列名匹配可以统一按文本处理。CSV 没有可靠的 Excel 类型元数据，按文本读取，但这一边界必须公开说明。公式遵守第 2.5 节的独立契约。

### 2.4 数据数量和归属必须守恒

1. 合并成功的每一来源行必须且只能进入目标一次，不得漏行、重行或串 Sheet。
2. 拆分各输出的数据行总数，加上有明确日志的跳过行数，必须等于来源有效数据行数。
3. 每个拆分值的数据只能进入对应文件，不得因非法字符替换、截断、大小写或重名而混组、覆盖。
4. 列顺序变化只允许改变位置，不得改变值、类型或业务归属。
5. 缺列、额外列、空拆分值、取消文件和跳过 Sheet 必须有可定位的日志或异常记录。

### 2.5 公式必须按产品契约处理

**合并：**

- 待合并文件中的公式按最后保存的计算缓存值导入，不复制依赖原位置的公式；
- 缓存值保持原数据类型；无缓存值时必须留空并记录明确警告；
- 模板中未被数据区覆盖的公式必须保持公式类型、公式文本和原位置；
- 列顺序打乱后，不得出现因位置引用变化导致的错误结果。

**拆分：**

- 支持范围内的公式必须继续保持公式类型；
- 删除拆分列、筛选行后，标准 A1 相对/绝对/区域引用必须移动到正确位置；
- 引用被删除列时必须产生明确且可解释的结果，不得偷偷引用相邻列；
- 必须由 Microsoft Excel 执行完整重算并核对结果，不能只检查公式字符串；
- 跨 Sheet、结构化引用、命名区域、动态数组和外部链接未验证前不得宣称支持。

### 2.6 失败必须明确

- 成功提示、退出码和最终文件必须一致；没有最终文件时不得提示成功。
- 文件被 Excel 占用、磁盘写入失败、权限不足、密码保护或格式不支持时，应说明具体原因和用户下一步。
- 日志不得只写 Python 堆栈；普通用户必须能看懂失败发生在哪个文件、Sheet 或步骤。

## 3. 合并与拆分的兼容性检查矩阵

以下项目每次发布都必须得到“通过 / 明确不支持 / 待修复”结论。凡程序会接收但可能静默破坏的内容，属于 P1 能力阻断。

| 对象 | 合并测试规则 | 拆分测试规则 | 等级 |
| --- | --- | --- | --- |
| 单元格样式 | 模板的字体、填充、边框、对齐、数字格式和保护属性在未覆盖区域保持；数据区显示格式按模板契约 | 检查字体、填充、边框、对齐和数字格式是否保留；未实现时必须明确说明，不得称为格式保真 | P1 |
| 行列与视图 | 检查列宽、行高、冻结窗格、隐藏行列、筛选、打印区域和隐藏 Sheet | 检查拆分后是否需要继承这些设置，并记录实际行为 | P1 |
| 合并单元格 | 模板合并区域不得损坏；写入区域与合并单元格冲突时必须阻止或明确报错 | 来源合并区域无法安全映射时必须阻止或明确警告 | P1 |
| 公式 | 检查模板公式保留、来源公式转缓存值、无缓存警告和 Excel 实际重算 | 检查公式移动、删除列引用、跨行筛选和 Excel 实际重算 | P0 |
| 宏/VBA | `.xlsm` 输出必须保持 `.xlsm`；验证 `vbaProject.bin` 存在且未被替换，并在真实 Excel 中运行公开测试宏 | 当前输出为 `.xlsx` 时不得静默接受含宏来源并丢弃宏；必须在处理前阻止或警告 | P1 |
| 按钮/ActiveX/签名 | 必须独立验证，不能用“VBA 部件存在”推断按钮、ActiveX 或签名有效 | 不支持时在处理前提示 | P1 |
| 图表/图片/形状 | 使用公开样例比较处理前后对象数量并进行 Excel 目视检查；发现丢失必须阻止或警告 | 同左 | P1 |
| 表格、条件格式、数据验证 | 检查对象范围是否随数据区变化且仍可用 | 检查拆分后范围和规则是否正确；不支持时明确说明 | P1 |
| 外部链接/命名区域 | 检查链接与名称是否存在、是否被改写，并在 Excel 中确认无修复提示 | 不支持时阻止或警告 | P1 |
| 工作簿/工作表保护 | 有密码或保护限制时不得绕过保护；无法写入时明确失败 | 同左 | P0 |

样式检查必须同时核对“底层属性”和“Excel 中的实际显示”。只检查单元格值不足以证明样式、数字格式或对象被保留。

## 4. 分层测试要求

1. **纯逻辑测试**：列匹配、分组、文件名、公式引用移动、异常决策。
2. **文件级测试**：创建公开合成工作簿，运行真实读写，再打开核对值、类型、公式、样式、对象和包完整性。
3. **CLI 黑盒测试**：启动独立进程，检查退出码、日志、原子输出和失败路径。
4. **GUI/EXE 冒烟**：使用打包产物完成至少一轮合并和拆分，不只检查 `--version`。
5. **真实 Excel 兼容测试**：打开、完整重算、保存、关闭、再次打开；确认无修复提示，并核对公式结果和关键视觉对象。

自动化测试应优先覆盖可稳定判断的规则。宏执行、图表外观、按钮、签名和不同 Excel 版本兼容性可人工验收，但必须使用可公开样例并保存结论。

## 5. 每版最低公开样例集

| 样例 | 必须覆盖 |
| --- | --- |
| 类型样例 | 整数、小数、负数、零、布尔、日期/时间、普通文本、前导零文本、空值、错误值 |
| 公式样例 | 合并公式缓存、无缓存、拆分相对/绝对/区域引用、删除列引用、Excel 重算 |
| 样式样例 | 字体、填充、边框、对齐、百分比/日期/货币格式、列宽、行高、冻结窗格、合并单元格 |
| 宏样例 | 可公开 `.xlsm`、一个可运行宏、按钮/ActiveX 分开记录 |
| 对象样例 | 图表、图片、形状、表格、条件格式、数据验证、命名区域、外部链接 |
| 异常样例 | 文件占用、无权限、输出已存在、密码/保护、损坏输入、取消操作、磁盘写入失败模拟 |
| 路径样例 | 中文、空格、多个点、长文件名、大小写冲突和 Windows 保留名 |

所有样例必须人工构造、匿名且可公开，不得从业务文件裁剪或脱敏后提交。

## 6. 发布证据与签字

发布记录至少包含：

- 提交号、版本号、操作系统、Python/openpyxl/PyInstaller/Excel 版本；
- 自动化测试数量和 CI 链接；
- 合并与拆分各自的样例清单、预期结果和实际结果；
- Excel 是否出现修复、兼容性或内容删除提示；
- 样式、公式、宏、图表/图片/形状等矩阵的结论；
- 尚未支持的内容及程序是否在处理前阻止或警告；
- 产品负责人最终确认。

发布不能以“文件能生成”作为通过标准。只有数据正确、类型正确、文件可正常打开、失败路径清楚，且高风险兼容项有明确结论时，才可以发布。
