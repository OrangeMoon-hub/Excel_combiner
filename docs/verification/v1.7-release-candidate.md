## 2. 自动化测试

执行命令：

```powershell
python -m unittest discover -s tests -v
```

结果：62 项通过。

- 原有文件级回归继续通过，新增格式/表格/图表/冻结窗格保留、空表格有效性、复杂公式拒绝和控件拒绝测试；
- 18 项 CLI、传统入口与核心结构测试通过；
- CLI 测试以独立 Python 进程执行，检查成功、输入不存在、Sheet 未映射、未确认列丢弃、拆分列不存在、输出冲突、无缓存公式警告、空拆分值日志、单 Sheet 重命名、帮助和版本；
- 输出工作簿由 openpyxl 重新打开并核对关键值及数值、布尔、日期、文本类型；
- 核心模块静态检查确认不导入 tkinter，也不保存列表、字典或集合形式的可变任务全局。

语法检查：

```powershell
python -m compileall -q excel_combiner 合并脚本.py 拆分脚本.py
```

结果：通过。

## 3. Windows EXE 构建与启动

本地环境：Windows 11、Python 3.13.7、PyInstaller 6.16.0。

构建命令与 GitHub Actions 使用相同参数：

```powershell
python -m PyInstaller --noconfirm --clean --onefile --console --name excel-merge 合并脚本.py
python -m PyInstaller --noconfirm --clean --onefile --console --name excel-split 拆分脚本.py
```

结果：两个入口均构建成功；执行 `--version` 均返回退出码 0 和版本 1.7。构建目录、spec 和 exe 均受 `.gitignore` 排除，不作为源码提交。

## 4. Microsoft Excel 打开检查

验证程序在系统临时目录生成公开、人工构造的最小工作簿，通过 CLI 生成一个合并结果和两个拆分结果，再使用本机 Microsoft Excel 以普通模式、只读方式逐个打开。

结果：原简单工作簿继续通过；另用公开合成的两 Sheet 增强样例生成六个拆分结果，全部正常打开、完整重算、保存并重开，未观察到修复日志。日期格式、货币/百分比格式、文本编号、布尔和数值类型、Excel 表格、同 Sheet 图表与冻结窗格均在适用输出中保留；无数据 Sheet 会移除无效空表格。研发组公式重算为 201、600 和 65000。

该检查覆盖指定 `.xlsx` 样例，不证明任意图片、形状、VBA、ActiveX、签名、外部连接或所有 Excel 版本兼容。程序对已知无法可靠保留的宏、控件和形状采取处理前拒绝。
