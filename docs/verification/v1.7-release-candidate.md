# Excel Combiner v1.7 发布候选验证记录

> 验证日期：2026-10-05
> 验证对象：`feature/v1.7-core-cli` 分支
> 文档状态：本地与 GitHub CI 验证完成，等待产品负责人发布确认

## 1. 验证结论

v1.7 发布候选已满足无界面核心、正式 CLI、原有行为回归、跨平台 CI、Windows EXE 构建和 Microsoft Excel 最小兼容检查。完整 GUI 点击自动化、宏运行和复杂绘图对象仍不在本版验证范围内。

## 2. 自动化测试

执行命令：

```powershell
python -m unittest discover -s tests -v
```

结果：49 项通过。

- 35 项原有文件级回归继续通过；
- 14 项 CLI、传统入口与核心结构测试通过；
- CLI 测试以独立 Python 进程执行，检查成功、输入不存在、Sheet 未映射、未确认列丢弃、拆分列不存在、输出目录冲突、单 Sheet 重命名、帮助和版本；
- 输出工作簿由 openpyxl 重新打开并核对关键值；
- 核心模块静态检查确认不导入 tkinter，也不保存列表、字典或集合形式的可变任务全局。

语法检查：

```powershell
python -m py_compile excel_combiner\*.py 合并脚本.py 拆分脚本.py
```

结果：通过。

## 3. Windows EXE 构建与启动

本地环境：Windows 11、Python 3.13.7、PyInstaller 6.16.0。

构建命令与 GitHub Actions 使用相同参数：

```powershell
python -m PyInstaller --noconfirm --clean --onefile --console --name excel-merge 合并脚本.py
python -m PyInstaller --noconfirm --clean --onefile --console --name excel-split 拆分脚本.py
```

结果：两个入口均构建成功；执行 `--version` 均返回退出码 0 和版本 1.7。构建目录、spec 和 exe 均受 `.gitignore` 排除，不作为源码提交。

## 4. Microsoft Excel 打开检查

验证程序在系统临时目录生成公开、人工构造的最小工作簿，通过 CLI 生成一个合并结果和两个拆分结果，再使用本机 Microsoft Excel 以普通模式、只读方式逐个打开。

结果：三个工作簿均正常打开并包含工作表，Excel 自动化未报告文件损坏或打开失败。临时输入与输出在检查结束后删除。

该检查只覆盖简单 `.xlsx` 数据工作簿。它不证明图表、图片、形状、VBA、ActiveX、签名、外部连接或所有 Excel 版本兼容。
