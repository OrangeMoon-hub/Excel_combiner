## 5. 缺陷清单

### QA-17-001 P0：合并 CLI 静默覆盖已有结果文件

- **涉及模块**：`excel_combiner/merge_core.py` 的 `run_merge`；`excel_combiner/cli.py` 的 merge 入口。
- **测试环境和 commit**：见第 3 节，`6b3f78c4e3b07d42941fd5d2fae0178b2127c488`。
- **前置条件**：模板和输入均有效；输出路径已经存在，且已有结果文件中包含不可覆盖的哨兵数据。
- **操作步骤**：
  1. 创建模板 `Data!A1=Name`；
  2. 创建输入 `Data!A2=NEW_DATA`；
  3. 预先创建输出文件，其中 `OldResult!A1=DO_NOT_OVERWRITE`；
  4. 执行 `python -m excel_combiner merge --template template.xlsx --input source.xlsx --output result.xlsx --sheet-map Data=Data`。
- **期望结果**：依据发布规则 2.1.2，应拒绝、要求显式覆盖，或生成不冲突的新文件；不得静默替换已有结果。
- **实际结果**：退出码 0，标准错误为空，输出 SHA256 改变，旧 Sheet 和哨兵数据消失，结果变为 `Data!A2=NEW_DATA`；模板与输入 SHA256 未改变。
- **代码证据**：`run_merge` 只在输出等于模板或输入时拒绝；随后无条件执行 `temporary.replace(output)`，会替换其他已有结果。
- **用户和发布影响**：重复运行或误选已有输出路径会造成用户结果文件不可恢复地被覆盖。属于直接数据损失风险，阻断发布。
- **建议排查方向**：统一 GUI 与 CLI 的防覆盖契约。默认拒绝已有输出或自动递增；如要支持覆盖，必须增加显式选项和用户可见确认。补 CLI 独立进程回归，断言退出码、原文件哈希和最终路径。

### QA-17-002 P0：无缓存公式被置空，但 CLI 成功且不显示任何警告

- **涉及模块**：`excel_combiner/merge_core.py` 的 `read_xlsx`、`run_merge`；`excel_combiner/cli.py`。
- **测试环境和 commit**：见第 3 节。
- **前置条件**：待合并 `.xlsx` 含公式 `=1+1`，公式没有最后保存的缓存值；模板存在对应列。
- **操作步骤**：运行合并 CLI，将该文件按 Sheet 映射到模板。
- **期望结果**：依据发布规则 2.5，允许结果留空，但必须记录明确警告；用户必须知道存在数据缺失。也可以按产品决定直接失败。
- **实际结果**：退出码 0，标准错误为空，标准输出只有“合并完成”；输出公式单元格重开后值为 `None`，没有日志或警告说明该值因缺少缓存而丢失。
- **代码证据**：`read_xlsx` 只有在传入 `logger` 时才发出缺缓存警告；CLI 调用 `run_merge` 时没有传 logger，也没有从结果模型取得警告。
- **用户和发布影响**：用户会把成功文件当作完整结果，公式数据却静默变为空值。属于静默数据丢失，阻断发布。
- **建议排查方向**：让核心返回结构化 warning，CLI 始终打印并可写日志；或把缺缓存升级为受控失败。增加 CLI 黑盒测试，必须检查退出码、警告文本和结果单元格。

### QA-17-003 P0：拆分 CLI 跳过空拆分值时没有可定位日志，守恒不可核对

- **涉及模块**：`excel_combiner/split_core.py` 的 `split_tables`；`excel_combiner/cli.py` 的 split 入口。
- **测试环境和 commit**：见第 3 节。
- **前置条件**：来源 Sheet 有两条有效数据行，其中一条拆分值为 `X`，另一条拆分值为空。
- **操作步骤**：运行拆分 CLI，按该列拆分。
- **期望结果**：输出行数加明确记录的跳过行数应等于来源有效行数；日志应定位 Sheet 和跳过数量或行。
- **实际结果**：退出码 0，只生成 `X.xlsx` 中的一条数据；标准输出只有“拆分完成：1 个文件”，标准错误为空，没有跳过数量、Sheet 或行的记录。
- **证据**：输出内容只有表头和 `kept` 行，检查结果 `SKIP_DETAIL_PRESENT=False`。
- **用户和发布影响**：来源行被有意跳过但成功摘要没有说明，无法证明数据守恒，用户可能误认为所有行都已处理。违反 P0 2.4.2、2.4.5。
- **建议排查方向**：将跳过计数和定位信息放入 `SplitRunResult` 或结构化日志，并让 CLI 默认输出摘要/日志路径。增加独立进程守恒测试。

### QA-17-004 P1：拆分后条件格式和数据验证的作用范围移动，但规则公式未移动

- **涉及模块**：`excel_combiner/split_core.py`，条件格式和数据验证重建逻辑。
- **测试环境和 commit**：见第 3 节。
- **前置条件**：Sheet 列为 `A=Group`、`B=Limit`、`C=Value`；条件格式应用于 `C2:C3`，公式为 `C2>B2`；数据验证应用于 `C2:C3`，`formula1=$B$2:$B$3`；按 A 列拆分。
- **操作步骤**：调用当前 `run_split` 并重新打开 `X.xlsx`。
- **期望结果**：删除 A 列后，条件格式应作用于 `B2`，规则应调整为 `B2>A2`；数据验证引用也必须按安全策略调整。无法可靠调整时应在写出前明确拒绝。
- **实际结果**：条件格式作用范围变为 `B2`，但公式仍为 `C2>B2`；数据验证作用范围变为 `B2`，但 `formula1` 仍为 `$B$2:$B$3`。
- **代码证据**：当前实现只重写 `sqref`，没有重写条件格式 rule formula、数据验证 `formula1/formula2`。
- **用户和发布影响**：条件高亮和数据验证会引用错误列/错误行，可能把无效数据当作有效，或丢失原有告警。README 宣称保留条件格式和数据验证，实际只保留对象外壳。涉及已公开能力，属于 P1 能力阻断。
- **建议排查方向**：对规则公式建立与单元格公式相同的安全解析与迁移；无法证明安全的公式型规则应前置拒绝。补底层公式断言和真实 Excel 显示/交互测试。
