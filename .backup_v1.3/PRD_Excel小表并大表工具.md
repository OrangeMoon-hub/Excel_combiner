# 产品需求文档 (PRD) — Excel 小表并大表工具

> 版本: v1.3  
> 日期: 2026-07-19  
> 修订: v1.2 新增大表拆分 / 标注来源可选 / 反向填表工作流  
> v1.3 拆分工具重构（Sheet 级配置 + 文件名/Sheet 名语义修正）+ 合并弹窗定位修复 + 输出自动递增防覆盖

---

## 1. 项目概述

### 1.1 背景
用户在日常数据处理中，需要：
- **正向合并**：将多个结构相似的 Excel 小表数据，按列名匹配的方式合并到一张大表中
- **反向填表**：数据库导出的多 Sheet 大表，按某列值拆分为多个小表，再合并到模板中

两条链路搭配使用，实现"导出→拆分→合并→数据刷新"的完整工作流。

### 1.2 目标
开发一套零依赖的轻量级 Python 工具：
- `合并脚本.py`：正向合并（v1.1 延续），新增可选功能
- `拆分脚本.py`：大表拆分（v1.2 新增），按指定列值将大表拆成多个小表

两个脚本可独立运行，也可串联使用。

### 1.3 核心原则
- 零第三方依赖（仅使用 Python 标准库）
- 打包为单文件 exe，无需安装 Python 环境
- 交互友好，异常情况弹窗让用户决策
- 两个工具职责分离，不相互耦合

### 2.1 工作流示例

```
场景: 数据库导出了大表（含"入职""离职""在职"三类数据），需要更新到各仓库模板中。

1. 拆分: 运行拆分脚本.py
   → 选择大表文件 → 选择拆分依据列 "数据类型"
   → 输出 拆分输出/入职.xlsx, 离职.xlsx, 在职.xlsx

2. 合并: 运行合并脚本.py
   → 选择模板文件（不勾"标注数据来源"）
   → 选择待合并文件 = 拆分输出/ 中的文件
   → 输出 合并结果.xlsx（全量刷新）

3. 如果需要保留老数据:
   → 将 老数据.xlsx + 合并结果.xlsx 再跑一次合并脚本
   → 得到最终的全量数据
```

## 3. 工具一：拆分脚本（v1.3 重构）

### 3.1 概述

将一张含多 Sheet 的大表，按用户选定的 Sheet 和各自的拆分依据列，拆分为多个小表文件。拆出的小表可直接作为合并脚本的输入，实现「拆分→合并」闭环。

**核心语义（v1.3 修正）：**
- **文件名** = 拆分列的值（对应合并脚本中自动填入"表名"列的值）
- **Sheet 名** = 原始大表中的 Sheet 名称（保留原名，对应合并脚本的 Sheet 匹配规则）
- **用户选中的所有 Sheet** 都汇入同一个输出文件（多 Sheet 子表）

### 3.2 用户交互流程

```text
 ┌──────────────────────────────────────────┐
 │  对话框一: 选择大表文件                     │
 │  ┌──────────────────────────────────┐    │
 │  │ ○ 合并结果.xlsx                   │    │
 │  │ ○ 大表导出_1月.xlsx               │    │
 │  └──────────────────────────────────┘    │
 │  单选（一次拆一张大表）                     │
 └───────────────────┬──────────────────────┘
                     ▼
 ┌──────────────────────────────────────────┐
 │  对话框二: Sheet 拆分配置（合并在一个界面）   │
 │                                            │
 │  大表: 合并结果.xlsx                        │
 │                                            │
 │  ┌─ Sheet ────┬─ 参与 ─┬─ 拆分依据列 ────┐ │
 │  │  试用期     │  ☑    │  [ 表名 ▼ ]      │ │
 │  │  正式名单   │  ☑    │  [ 表名 ▼ ]      │ │
 │  │  统计汇总   │  ☐    │  -              │ │
 │  │  台账       │  ☑    │  [ 仓库 ▼ ]     │ │
 │  └────────────┴───────┴─────────────────┘ │
 │                                            │
 │  说明: 下拉框列出该 Sheet 的所有列名          │
 │         默认选中第一列的列名                   │
 │                                            │
 │  [上一步]                    [开始拆分]      │
 └───────────────────┬──────────────────────┘
                     ▼
 ┌──────────────────────────────────────────┐
 │  拆分处理                                  │
 │  ├─ 收集所有选中 Sheet 的所有拆分列唯一值     │
 │  ├─ 每个唯一值 → 一个输出文件               │
 │  ├─ 输出文件包含全部选中 Sheet              │
 │  │   ├─ 该 Sheet 有匹配行 → 含数据          │
 │  │   └─ 该 Sheet 无匹配行 → 仅含表头        │
 │  ├─ 拆分依据列从数据中删除                   │
 │  └─ 写入 拆分输出/{列值}.xlsx               │
 └───────────────────┬──────────────────────┘
                     ▼
         拆分输出/
         ├── 华为.xlsx
         │   ├── Sheet「试用期」
         │   ├── Sheet「正式名单」
         │   └── Sheet「台账」
         ├── 小米.xlsx
         │   ├── Sheet「试用期」
         │   ├── Sheet「正式名单」
         │   └── Sheet「台账」
         └── 甲类.xlsx
             ├── Sheet「试用期」
             ├── Sheet「正式名单」
             └── Sheet「台账」
```

### 3.3 功能需求

| ID | 需求描述 | 优先级 |
|----|---------|-------|
| S0 | **单选大表**：一次拆分一张大表，不再支持多选 | P0 |
| S1 | **所有 Sheet 均展示**：读取大表全部 Sheet，每个 Sheet 都出现在配置界面中 | P0 |
| S2 | **每个 Sheet 独立配置**：可各自勾选是否参与拆分，各自选择拆分依据列 | P0 |
| S3 | **拆分列下拉默认第一列**：每个 Sheet 的下拉框默认选中该 Sheet 表头第一列的列名 | P0 |
| S4 | **Sheet 名称保留**：输出文件中 Sheet 使用原始 Sheet 名称，不改为拆分列值 | P0 |
| S5 | **文件名使用拆分列值**：输出文件名 = 拆分列值.xlsx | P0 |
| S6 | **多 Sheet 汇入同一文件**：所有选中 Sheet 的数据汇入同一输出文件（智能合并） | P0 |
| S7 | **拆分列值去重汇总**：所有 Sheet 的拆分列值取并集，每个唯一值一个输出文件 | P0 |
| S8 | **无匹配行保留表头**：某输出文件中某 Sheet 无对应行时，保留表头行不丢结构 | P1 |
| S9 | **拆分列值允许不同列名**：不同 Sheet 可选用不同的列作为拆分依据（如试用期用"表名"，台账用"仓库"） | P0 |
| S10 | 拆分后**删除拆分依据列**，其他列全部保留 | P0 |
| S11 | 拆分列值为空的行**自动跳过**，记录到日志 | P0 |
| S12 | 非法文件名字符（`/ \ : * ? " < > | [ ]`）自动替换为 `_` | P0 |
| S13 | Sheet 名最长 31 字符（Excel 限制），超长自动截断 | P1 |
| S14 | **输出文件夹自动递增**：`拆分输出/` 已存在时自动命名为 `拆分输出_2/`、`拆分输出_3/`… 不再弹窗确认覆盖，避免误覆盖 | P0 |
| S15 | **配置界面合并在单个对话框**：文件选择 + Sheet 配置两步完成，不拆散多个弹窗 | P1 |
| S16 | **合并脚本输出自动递增**：`合并结果.xlsx` 已存在时自动命名为 `合并结果_2.xlsx`、`合并结果_3.xlsx`… | P0 |

### 3.4 输出

| 输出 | 说明 |
|------|------|
| `拆分输出/` 文件夹 | 按拆分列值命名的多个 xlsx 文件 |
| 每个文件含多个 Sheet | Sheet 名 = 原始大表中的 Sheet 名（匹配合并脚本的规则） |
| 文件名 = 拆分列值 | 将来合并时自动填入"表名"列 |
| `拆分日志.txt` | 拆分过程日志（行数、跳过的空行等） |

### 3.5 注意事项

- **与合并脚本的对接**：拆分输出的文件名 → 合并脚本的"表名"列值；Sheet 名 → 合并脚本的 Sheet 匹配键
- **不同 Sheet 不同列**：因为允许不同 Sheet 选不同拆分列，同一个输出文件中，不同 Sheet 的"拆分键"语义可能不同（比如试用期按"表名"拆，台账按"仓库"拆）。这是设计意图，用户需自行确认逻辑一致性
- **未勾选的 Sheet 不出现在输出文件中**
- **跨表去重**：拆分不做去重，仅按值分组。去重交给合并流程或由用户自行处理

## 4. 工具二：合并脚本（v1.2 增强）

### 4.1 概述

从 v1.1 继承所有功能，新增两项改动。

### 4.2 改动一："标注数据来源"可选

#### 问题
v1.1 强制要求模板第一列为"表名"，但业务部门提供的模板通常不含这个列。

#### 方案
在模板选择对话框新增复选框：

```
┌─ 选择模板文件 ─────────────────────────────────┐
│                                                │
│  ○ 文件A.xlsx                                  │
│  ○ 文件B.csv                                   │
│                                                │
│  ☑ 标注数据来源                                 │
│     勾选后自动在首列插入"表名"列，                │
│     记录每行数据来自哪个文件                     │
│                                                │
│  [ 确定 ]                                       │
└────────────────────────────────────────────────┘
```

| 状态 | 行为 | "表名"列校验 | 合并时首列处理 |
|------|------|:----------:|:------------:|
| ☑ 勾上（默认） | v1.1 行为不变 | 强制校验 | 自动填入来源文件名 |
| ☐ 不勾 | 按模板原样合并 | 跳过校验 | 按普通列名匹配 |

| ID | 需求描述 | 优先级 |
|----|---------|-------|
| M0 | 模板选择对话框新增 checkbox `标注数据来源`，默认勾上 | P0 |
| M1 | 勾上时：校验模板首列必须为"表名"，合并时自动填入来源文件名（**向前兼容 v1.1**） | P0 |
| M2 | 不勾时：跳过"表名"校验，全部列按名称匹配，不自动填入来源 | P0 |
| M3 | 不勾时模板有此列但不需要自动填入→当普通列处理，按值匹配 | P1 |

### 4.3 改动二：模板文件可被合并

#### 问题
v1.1 硬编码排除模板文件，但反向填表工作流中模板可能同时是数据来源（合并结果也可以作为下一次合并的数据源）。

#### 方案
待合并文件列表中保留模板文件，默认不勾选，标记 `[📌模板]`：

```
┌─ 选择待合并文件 ─────────────────────────────────┐
│  勾选要合并的文件。模板文件 [📌模板] 默认不勾选。     │
│                                                  │
│  ☐ 被填充表.xlsx  [📌模板]                        │
│  ☑ 小表.xlsx  ██                                 │
│  ☑ 小表2.xlsx ██                                 │
│  ☑ 小表3.xlsx ██                                 │
│                                                  │
│  [全选]  [确定]                                   │
└──────────────────────────────────────────────────┘
```

| ID | 需求描述 | 优先级 |
|----|---------|-------|
| M4 | 模板文件出现在待合并列表，默认不勾，标记 `[📌模板]` | P0 |
| M5 | 全选按钮**不包括**模板文件（模板默认不勾） | P0 |
| M6 | 用户可手动勾上模板参与合并（如果模板含数据行） | P1 |

### 4.4 改动三（v1.3）：弹窗定位统一

#### 问题
合并过程中多个弹窗位置不一致——前半段弹窗（文件选择、同名列冲突）由窗口管理器随意放置，后半段弹窗（超表头列数、无列名检测、丢弃列确认）固定在 root 窗口的 `(80, 80)` 偏移处。用户操作过程中弹窗位置反复跳变，影响使用体验。

#### 方案
所有弹窗统一加 `dlg.geometry('+%d+%d' % (rx + 80, ry + 80))` 定位，相对于 root 窗口固定偏移，不再依赖窗口管理器默认位置。

**涉及弹窗：**

| 弹窗 | 修复前 | 修复后 |
|------|--------|--------|
| `_template_file_dialog` | 无定位 | `root + (80, 80)` |
| `_merge_files_dialog` | 无定位 | `root + (80, 80)` |
| `_dup_col_multi_dialog` | 无定位 | `root + (80, 80)` |
| `_extra_cols_dialog` | 已有（不变） | - |
| `_no_header_dialog` | 已有（不变） | - |
| `_discarded_cols_dialog` | 已有（不变） | - |

| ID | 需求描述 | 优先级 |
|----|---------|-------|
| M7 | 合并脚本所有弹窗统一使用 `root + (80, 80)` 定位 | P0 |
| M8 | 合并脚本输出 `合并结果.xlsx` 已存在时自动递增（`合并结果_2.xlsx`），不覆盖 | P0 |

## 5. 数据解析（两个工具共用）

| F7 | 零依赖 xlsx 解析（zipfile + ElementTree） | P0 |

## 6. 合并功能（从 v1.1 继承，不变）

以下功能 v1.2 全部保留，无改动：

- **同名列三步判断**：值一致→自动填入 / 数量相等→顺序填入 / 多列→弹窗选择
- **异常检测**：超表头列数、无列名、列名不存在于大表、同名列未选择
- **异常记录 Sheet**：10 字段逐条记录
- **取消合并的表名 Sheet**：被跳过/取消的文件及原因
- **输出文件**：合并结果.xlsx + 合并日志.txt
- **安全措施**：大表快照保护、源文件只读、输出覆盖确认

## 7. 技术方案

### 7.1 运行环境
- Python 3.6+（开发环境）
- Windows / Linux / macOS

### 7.2 技术栈

| 组件 | 选型 | 说明 |
|------|------|------|
| xlsx 解析 | `zipfile` + `xml.etree.ElementTree` | Python 内置，零依赖 |
| xlsx 写入 | `zipfile` + 手动构建 XML | Python 内置，零依赖 |
| GUI 对话框 | `tkinter` | Python 内置，零依赖 |
| 打包工具 | PyInstaller | 唯一构建期依赖 |

### 7.3 文件组成

```
合并脚本.py          ← 正向合并（v1.2 增强）
拆分脚本.py          ← 大表拆分（v1.2 新增）
合并结果.xlsx        ← 合并输出（运行时生成）
合并日志.txt         ← 合并日志
拆分日志.txt         ← 拆分日志
拆分输出/            ← 拆分输出文件夹（运行时生成）
```

### 7.4 安全措施
- **大表快照保护**：启动时将大表完整读入内存，后续不受外部修改影响
- 输出文件与源文件分离，源文件全程只读不写
- 拆分输出文件夹覆盖前弹窗确认

### 7.5 打包命令

```bash
pip install pyinstaller
pyinstaller --onefile --console 合并脚本.py
pyinstaller --onefile --console 拆分脚本.py
```

> ⚠️ **tkinter 跨平台注意事项：** `padx`/`pady` 在所有 widget 构造函数及 `.pack()` 中**必须使用单个整数值**，不可使用元组。Windows tkinter 不支持元组间距。

## 8. 边界情况与约束

### 8.1 合并脚本边界

| # | 场景 | 处理方式 |
|---|------|---------|
| 1 | 目录中没有小表 | 弹窗提示，退出 |
| 2 | 模板文件不存在 | 弹窗提示，重新选择 |
| 3 | 小表没有数据行（仅表头） | 跳过该小表 |
| 4 | 小表有不存在的 Sheet | 按 F5a 规则处理 |
| 5 | 大表只有表头没有数据行 | 将小表数据逐行追加 |
| 6 | 大表文件被其他程序打开 | 捕获异常，提示用户 |
| 7 | xlsx 文件损坏 | 捕获异常，跳过并记录 |
| 8 | 合并结果.xlsx 已存在 | 自动递增为 `合并结果_2.xlsx`、`合并结果_3.xlsx`… |
| 9 | `~$` 临时锁文件 | 自动跳过 |
| 10 | 不勾"标注来源"时模板无"表名"列 | 正常合并，不报错 |

### 8.2 拆分脚本边界

| # | 场景 | 处理方式 |
|---|------|---------|
| S-B1 | 拆分列值含非法文件名字符 | 自动替换为 `_`，记录日志 |
| S-B2 | 拆分列值为空 | 跳过该行，记录日志 |
| S-B3 | 所有 Sheet 某拆分列值全相同 | 只产出 1 个文件 |
| S-B4 | 某 Sheet 的勾选列在该 Sheet 中不存在 | 下拉框列表中不会出现（仅在读表时从该 Sheet 列名获取），如代码异常则跳过该 Sheet 并记录日志 |
| S-B5 | 拆分输出/ 已存在 | 自动递增为 `拆分输出_2/`、`拆分输出_3/`… |
| S-B6 | Sheet 名超 31 字符 | 自动截断前 31 字符 |
| S-B7 | 大表所有 Sheet 均无数据行 | 提示"无数据" |
| S-B8 | 不同 Sheet 选用了不同的拆分列 | 正常处理；同值文件汇集多个 Sheet；用户需自行确认逻辑一致性 |
| S-B9 | 用户未勾选任何 Sheet | 弹窗提示"请至少选择一个 Sheet" |
| S-B10 | 某 Sheet 在某输出文件中无匹配行 | 该 Sheet 仅保留表头行（保留列结构），不报错 |

### 8.3 tkinter 红线（两工具通用）

- **任何 widget 的 `padx`/`pady` 必须使用单个整数值，禁止使用元组**
- `.pack()` 中的 `padx`/`pady` 同样是单整数
